# 余境 · 虚拟艺术馆

安装：`npm ci`

本地启动：`npm run dev`

Docker 启动：`docker compose up --build`，访问 http://localhost:18112 。

## 策展故事（分支叙事）

主线之外新增一条由观众回答驱动的策展故事「回声之径」，入口在中央的「开启分支故事」或「主题导览 → 策展故事」。

- `src/shared/story.ts`：故事图（章节、问题、选项、封闭展区）与讲解轨道构造。
- `src/features/story/lib/storyMachine.ts`：纯函数状态机（到达、讲解结束、选择、重做、暂停、恢复校验）。
- `src/features/story/model/useStory.ts`：把状态机接到 React，并把讲解回调绑到「故事版本号」。
- `src/features/story/ui/StoryPanel.tsx`：故事面板、路线、回顾与悬浮状态条。

规则：

1. 只有走到章节对应作品前，讲解才开始；只有讲解真正播完，问题才出现，避免跳过未听的段落。
2. 每个章节的选项会改写其后的路线。同一作品可被再次经过（如 `n-tide` / `n-tide-again`），语境与字幕不同；收藏始终以作品 id 存储，只有一条。
3. 只允许「重做上一个已作答的选择」。更早的选择会破坏已经讲述的因果顺序，尚未到达的选择自然不会出现。重做会截断当前路线并丢弃该选择之后的进度，但已听过的事实与已发放的章节奖励保留；被放弃路径的完成度不会混入当前路线（见 `storyRecap.routeRewardCount`）。
4. 分支可以因展区封闭（`closedZones`）而不可达：选项保留可见但禁用，并说明原因；恢复旧存档时若经过封闭分支，会回退到该选择处。
5. 空间导航、字幕、回顾都读取同一个 `StoryRun.version`：任何状态迁移都会让版本号 +1，从而让旧讲解回调、旧计时器与旧目标失效。
6. 讲解临近结束、导航途中、刷新恢复时修改选择：`finishChapter` / `chooseOption` / `rewindToPreviousChoice` 都接收版本号，版本不匹配的调用是 no-op。
7. 刷新恢复时校验持久化路线与当前故事图，保留最长有效前缀，丢弃与版本不一致的选择，并回到执行该选择前的章节，以便重新讲解；不会自动标记完成或重复发奖。
8. 「回看」是只读播放，不会改动 `StoryRun`，因此不会破坏因果顺序。

测试：`npm test`（状态机、事实/奖励日志、以及 App 级的空间-字幕-回顾一致性流程）。
